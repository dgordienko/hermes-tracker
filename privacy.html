1. Introduction

1. Введение

1. Вступ

Hermes Tracker ("the app") is an internal Android application used by company field sales agents and couriers to record vehicle routes and confirm delivery visits. This policy explains what data the app collects, how it is used, and how it is retained. The app is distributed internally to authorized company staff and is not intended for the general public.

Hermes Tracker («приложение») — внутреннее Android-приложение, которое используют торговые агенты и курьеры компании для записи маршрутов транспорта и подтверждения визитов на точки доставки. Настоящая политика описывает, какие данные собирает приложение, как они используются и как долго хранятся. Приложение распространяется внутри компании среди авторизованных сотрудников и не предназначено для широкой публики.

Hermes Tracker («застосунок») — внутрішній Android-застосунок, який використовують торгові агенти та кур'єри компанії для запису маршрутів транспорту й підтвердження візитів на точки доставки. Ця політика описує, які дані збирає застосунок, як вони використовуються та як довго зберігаються. Застосунок поширюється всередині компанії серед авторизованих співробітників і не призначений для широкого загалу.

2. Data We Collect

2. Какие данные мы собираем

2. Які дані ми збираємо

  • Location data — precise GPS coordinates, speed, accuracy and timestamp, recorded while an agent actively starts route recording (in the foreground, and in the background if that permission is granted).
  • Delivery check-in data — which delivery point was visited, the calculated distance to that point, and the check-in timestamp.
  • Coordinate refinement data — an updated position for a delivery point when an agent corrects it, plus the time of the correction.
  • Device identifiers — a random device identifier generated and stored locally on the device, and the Google Advertising ID, both sent with server requests to identify the device/agent.
  • Diagnostic data — crash reports and error information collected via Sentry, which may include device model, OS version, and app state at the time of the error.
  • Геоданные — точные координаты GPS, скорость, точность и метка времени, записываемые, пока агент активно ведёт запись маршрута (на переднем плане и в фоне, если предоставлено соответствующее разрешение).
  • Данные чек-ина на точке доставки — какая точка доставки была посещена, рассчитанное расстояние до неё и время чек-ина.
  • Данные уточнения координат — обновлённая позиция точки доставки, когда агент её корректирует, и время этой корректировки.
  • Идентификаторы устройства — случайный идентификатор устройства, сгенерированный и хранящийся локально на устройстве, и рекламный идентификатор Google (Advertising ID), которые передаются с запросами на сервер для идентификации устройства/агента.
  • Диагностические данные — отчёты о крашах и ошибках, собираемые через Sentry; могут включать модель устройства, версию ОС и состояние приложения в момент ошибки.
  • Геодані — точні координати GPS, швидкість, точність та мітка часу, що записуються, поки агент активно веде запис маршруту (на передньому плані та у фоні, якщо надано відповідний дозвіл).
  • Дані чек-іну на точці доставки — яку точку доставки відвідано, розраховану відстань до неї та час чек-іну.
  • Дані уточнення координат — оновлену позицію точки доставки, коли агент її коригує, та час цього коригування.
  • Ідентифікатори пристрою — випадковий ідентифікатор пристрою, згенерований і збережений локально на пристрої, та рекламний ідентифікатор Google (Advertising ID), які передаються із запитами на сервер для ідентифікації пристрою/агента.
  • Діагностичні дані — звіти про краші та помилки, що збираються через Sentry; можуть містити модель пристрою, версію ОС і стан застосунку на момент помилки.

3. How We Use Data

3. Как мы используем данные

3. Як ми використовуємо дані

Location and check-in data are transmitted to the company's server to reconstruct and validate delivery routes, verify delivery visits, and maintain business records. Data is not used for advertising and is not sold to third parties. Diagnostic data is used only to identify and fix bugs.

Геоданные и данные чек-инов передаются на сервер компании для восстановления и проверки маршрутов доставки, подтверждения визитов и ведения деловой отчётности. Данные не используются в рекламных целях и не продаются третьим лицам. Диагностические данные используются исключительно для выявления и исправления ошибок.

Геодані та дані чек-інів передаються на сервер компанії для відновлення й перевірки маршрутів доставки, підтвердження візитів і ведення ділової звітності. Дані не використовуються в рекламних цілях і не продаються третім особам. Діагностичні дані використовуються виключно для виявлення та виправлення помилок.

4. Data Retention

4. Хранение данных

4. Зберігання даних

  • On the device — recorded tracks are stored locally until successfully uploaded, then automatically deleted from the device on the following calendar day.
  • On the server — retained according to the company's internal record-keeping requirements.
  • На устройстве — записанные треки хранятся локально до успешной выгрузки, после чего автоматически удаляются с устройства на следующий календарный день.
  • На сервере — хранятся в соответствии с внутренними регламентами компании по ведению учёта.
  • На пристрої — записані треки зберігаються локально до успішного вивантаження, після чого автоматично видаляються з пристрою наступного календарного дня.
  • На сервері — зберігаються відповідно до внутрішніх регламентів компанії щодо ведення обліку.

5. Third-Party Services

5. Сторонние сервисы

5. Сторонні сервіси

  • Sentry — crash and error monitoring.
  • OpenStreetMap map tiles (via osmdroid) — used to display route maps; no Google Maps SDK or API key is used for this feature.
  • Google Play services location APIs — used to obtain GPS position.
  • Sentry — отслеживание крашей и ошибок.
  • Тайлы карт OpenStreetMap (через osmdroid) — используются для отображения карты маршрута; для этой функции не используется Google Maps SDK и API-ключ.
  • Location API сервисов Google Play — используются для получения GPS-позиции.
  • Sentry — відстеження крашів і помилок.
  • Тайли карт OpenStreetMap (через osmdroid) — використовуються для відображення карти маршруту; для цієї функції не використовується Google Maps SDK і API-ключ.
  • Location API сервісів Google Play — використовуються для отримання GPS-позиції.

6. Permissions Explained

6. Разъяснение разрешений

6. Пояснення дозволів

  • Location (foreground) — required to record the route while the app is open.
  • Background location — required to continue recording the route while the screen is off or the app is not in the foreground.
  • Notifications — used to show an ongoing status notification while recording is active.
  • Геолокация (на переднем плане) — необходима для записи маршрута, пока приложение открыто.
  • Фоновая геолокация — необходима, чтобы продолжать запись маршрута при выключенном экране или когда приложение не на переднем плане.
  • Уведомления — используются для отображения текущего статуса записи в виде уведомления.
  • Геолокація (на передньому плані) — потрібна для запису маршруту, поки застосунок відкрито.
  • Фонова геолокація — потрібна, щоб продовжувати запис маршруту при вимкненому екрані або коли застосунок не на передньому плані.
  • Сповіщення — використовуються для відображення поточного статусу запису у вигляді сповіщення.
